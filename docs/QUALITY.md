# Quality contract

[Русская версия](QUALITY.ru.md) · [Contributing](../CONTRIBUTING.md)

A change is ready only when `./scripts/quality.sh` passes and the review checklist is satisfied. Failed checks mean revise the change, not lower a threshold or hide a function. The maintainer explicitly authorized the committed tests, fixtures generated by tests, hooks and CI in this policy on 2026-11-07.

## Principles in this application

- **DRY:** archive behavior belongs in ArcboxCore. GUI, JSON CLI and MCP call it. Streaming and SHA-256 accounting share one implementation for split, join and verification. Share a proven rule; do not merge merely similar-looking UI.
- **KISS:** use direct Swift value types, Foundation and native macOS controls. A helper should name a real responsibility. Avoid splitting code into meaningless wrappers just to meet a metric.
- **YAGNI:** implement the current Open/Create/Extract journey. No speculative plugin framework, settings or parallel execution infrastructure.
- **SOLID / SRP:** keep archive orchestration, engine processes, listing interpretation, output validation and part streaming separate. Adapters own presentation and protocol details; core has no dependency on either adapter.

## Blocking checks

| Check | Limit | Tool and measured scope |
| --- | --- | --- |
| Formatting | No differences or diagnostics | Xcode 16.4 `swift-format`; Sources, Tests, Package.swift |
| Safety and size lint | No warnings; file ≤500, function ≤80, type ≤450 lines | SwiftLint 0.65.1; Sources and Tests; body lengths exclude comments/blank lines |
| Cyclomatic complexity | Every function/accessor ≤10 | swift-complexity 1.6.0, SwiftSyntax; all production Swift in Sources |
| Cognitive complexity | Every function/accessor ≤15 | Same analyzer and scope |
| CRAP(line) | Mean <5; maximum ≤30 | Complexity above + LLVM executable-line coverage; all measured ArcboxCore functions |
| Diff coverage | ≥80% of changed executable lines | LLVM → Cobertura → diff-cover 9.7.0; ArcboxCore Swift |
| Circular dependencies | 0 module cycles; core cannot depend on adapters | Resolved SwiftPM target graph + compiler |
| Behavior | All XCTest and SwiftCheck properties pass | Synthetic archives, parts, encryption, cancellation, unsafe paths, limits and atomic outputs |
| Mutation sensitivity | All generated mutants in the declared scope killed; nonempty run | Muter 16; `ArchivePathPolicy.swift`, `PartStream.swift`; relational and logical connector replacement |
| Translations | Matching keys and printf placeholders | plutil + catalog contract check; EN/RU |
| Quality-tool Python | Ruff lint/format; McCabe ≤10 | Ruff 0.14.4; scripts/quality and Python tests |
| CLI/MCP contract | JSON results, exit codes, stdin passwords, multipart and MCP negotiation/tools pass | Python unittest through compiled arcbox |
| Gate reliability | All gate contract tests pass | Python unittest; formula, LLVM region mapping, empty data, failures, graph cycles and exact staged-tree validation |

Inline lint/complexity suppressions are rejected. There is no legacy baseline exemption. `.swiftlint.yml`, `.swift-format`, the quality scripts and this policy are reviewed together. The formatter intentionally allows the established `L(...)` localization helper and SwiftUI's named work/trailing completion convention.

### What the numbers mean

CRAP(line) is `C² × (1 − coverage)³ + C`, with coverage in 0…1. We use **executable-line coverage**, not basis-path coverage or branch coverage. The adapter matches SwiftSyntax function starts to LLVM outer code regions; unmatched functions receive zero coverage. `.build/quality/metrics.json` exposes every function, matched region and score. This is a documented line-coverage variant, not a claim to measure the original path-based metric.

Diff coverage uses the supplied Git base and includes staged/working changes locally. CI supplies the PR base SHA; main-branch runs compare with the preceding push revision. A change without executable core lines has no diff-coverage denominator. That does not establish coverage for UI or protocol code.

Coverage and CRAP currently gate **ArcboxCore**. SwiftUI/AppKit and CLI/MCP are compiled and included in complexity/size checks, but do not yet have automated coverage gates. UI journeys, resizing, animation, Reduce Motion and protocol behavior still need explicit verification for relevant changes beyond the automated CLI/MCP contract cases. A module-cycle check does not prove absence of every cycle among types inside one module.

SwiftCheck generates 100 cases per property, with shrinking and failure replay seeds in test output. Preserve a failing seed when investigating a failure. Boundary and error examples complement the properties.

The mutation gate is deliberately bounded to two critical rules: unsafe archive names must fail; streaming must honor part boundaries. Its score is **not a project-wide mutation score**. Muter 16 misplaces mutations after non-ASCII source text in some files; the declared pure policy/streaming files are ASCII and were verified to compile under mutation. Expand the scope with behavioral tests and a verified tool upgrade, rather than reporting unsupported coverage as success. Timeouts, surviving mutants, empty runs and compilation/environment errors fail the gate.

## Local workflow

Use macOS and Xcode **16.4 / Swift 6.1.2**, selected through Xcode or `DEVELOPER_DIR`. Homebrew is needed for development tools, not for the shipped app.

```sh
./scripts/setup-quality.sh
xcrun swift-format format --in-place --recursive Sources Tests Package.swift
./scripts/quality.sh --base origin/main
```

Setup installs SwiftLint, Muter and uv, downloads the pinned/checksummed complexity analyzer, resolves the committed SwiftPM lockfile, installs hash-locked diff-cover/Ruff into an ignored Python 3.12 virtual environment and enables the versioned Git hook. Versions are checked rather than silently substituted. If Homebrew offers a different version, use the documented version or propose a tool-version update; a passing check under an unreviewed version is insufficient.

Before committing, stage the intended change. The hook refuses unstaged tracked changes or untracked files so the validated source matches the commit. It also refuses working-tree or staging changes made while checks are running. Stash unrelated work when needed. The hook runs the **same full gate**, including mutation tests, against HEAD; expect a few minutes. It does not modify source files. Reports and tool caches live under ignored `.build/`.

A hook is local and bypassable; GitHub's required `Quality / gate` check and PR requirement protect main. The workflow runs for all PRs and pushes, with read-only token permissions and no secrets. Failed reports are downloadable as workflow artifacts. There are no path filters that could leave a required check missing.

Useful focused commands while editing:

```sh
swift test --enable-code-coverage
swiftlint lint --strict
./scripts/quality/mutation.sh
```

Focused commands do not replace the full pre-commit gate. Do not use `--no-verify`, lower limits, add exclusions or delete assertions to get a green result. If a tool is unavailable or a metric is inappropriate, explain the specific limitation in the PR and propose a policy change for maintainer review.

## Human review checklist

- What user/agent behavior changes, and which requirement needs it?
- Does each changed module have one coherent reason to change?
- Is a rule duplicated between GUI, CLI, MCP or archive operations?
- Is the simplest implementation sufficient for today's requirement?
- Are originals preserved and outputs published atomically? What happens on failure/cancel?
- Do tests assert observable behavior and detect relevant defects?
- Does every noticeable wait have truthful animated feedback, cancellation where supported and Reduce Motion support?
- Are EN/RU, data safety and the Open/Create/Extract journey consistent?

Passing tools cannot certify DRY, KISS, YAGNI or SOLID. These questions remain required review work.
