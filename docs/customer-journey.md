# Путь пользователя: один архив, сколько бы ни было частей

[English](customer-journey.en.md) · **Русский**

Основное намерение: упаковать файлы для передачи или получить файлы из
полученного архива. Разбиение и сборка являются свойствами этих действий.
В интерфейсе нет отдельного раздела или команды «Части».
В шапке три основных действия: «Открыть», «Создать», «Распаковать».
Боковую панель можно плавно скрыть и вернуть кнопкой слева в шапке или
Ctrl+Cmd+S; выбранное состояние запоминается. При уменьшении движения в macOS
переход мгновенный.

## Получить файлы из многотомного архива

| Шаг | Действие человека | Ответ Arcbox |
| --- | --- | --- |
| Вход | «Открыть», Finder или перетаскивание части | Находит первый том и соседние части; можно выбрать не первую часть. Перетаскивание нескольких частей одного набора также открывает этот набор. |
| Понимание | Смотрит содержимое | Показывает логическое имя архива, суммарный размер всех томов и число частей. В недавних это один архив. |
| Выбор | Нажимает «Распаковать» или выбирает нужные файлы | Спрашивает только папку назначения. Ручная промежуточная сборка не требуется. |
| Выполнение | Ждёт или отменяет | Читает все тома, проверяет manifest при наличии, извлекает во временную папку. |
| Результат | Открывает результат в Finder | Только после успеха публикует новую папку с файлами; исходные части сохраняются. |

Входы: числовые `.001/.002`, `.partNN.rar`, старые `.rar/.r00` и разделённые
ZIP `.z01/.zip`. Набор без упаковки открывается тем же действием: внутри
показан один исходный файл, «Распаковать» восстанавливает его в новой папке.
Для manifest можно выбрать сам `.arcbox-parts.json`.

## Подготовить архив для передачи

| Шаг | Действие человека | Ответ Arcbox |
| --- | --- | --- |
| Вход | «Создать» или перетаскивание исходных файлов | Открывает одну форму создания. |
| Состав | Выбирает файлы/папки и ZIP, 7z или TAR | Показывает выбранное, параметры сжатия и пароль там, где они поддерживаются. |
| Ограничение передачи | При необходимости включает «Разделить на части», выбирает максимальный размер | Вся настройка остаётся в той же форме; последняя часть может быть меньше. |
| Назначение | Выбирает имя и место результата | Для обычного архива сохраняется файл, для частей создаётся одна папка набора. |
| Результат | Передаёт папку набора | В ней части `.001/.002/...` и manifest SHA-256. Промежуточная полная копия архива пользователю не выдаётся. Набор сразу открывается в Arcbox. |

Для уже готового большого файла есть формат результата «Части исходного файла
(.001)». Он доступен внутри «Создать», принимает один файл и не добавляет
упаковку. Восстановление выполняется через «Открыть → Распаковать».

## Ошибка должна говорить, что делать дальше

| Ситуация | Поведение |
| --- | --- |
| Нет первого или среднего тома | Показывает конкретное ожидаемое имя и просит положить части в одну папку. После добавления файла достаточно «Повторить». |
| Нет последней части из manifest | Называет недостающий файл до распаковки. |
| Размер части не совпал | Объясняет, что загрузка может быть не завершена. |
| SHA-256 части не совпала | Называет повреждённый файл, не публикует частичный результат. |
| Нужен пароль | Запрашивает пароль внутри текущей операции и продолжает её. |
| Путь назначения уже существует | Не заменяет существующие данные. В GUI автоматически предлагает свободное имя папки. |
| Отмена или ошибка создания/распаковки | Очищает незавершённый результат; источники сохраняются. |

Без manifest отсутствие последней части произвольного бинарного файла
достоверно не определить. После восстановления такого набора статус сообщает,
что полнота не подтверждена. Для настоящего архива дополнительно действуют
его структура и контрольные суммы; ошибка чтения не считается успехом.

## Агент проходит те же пути

- `list` принимает любую часть и возвращает `volumes`, `isFileParts` и содержимое.
- `create` принимает необязательный `partBytes`; с ним `output` означает новую
  папку набора. Возвращает путь, число частей и `firstPart`.
- `extract` принимает любую часть и сам использует весь набор.
- MCP использует эти же контракты. Низкоуровневые `split`/`join` сохранены
  для совместимости CLI/MCP, но не образуют отдельного пользовательского режима.
