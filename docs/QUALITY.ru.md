# Контракт качества

[English](QUALITY.md) · [Участие](../CONTRIBUTING.md)

## Обычная работа

```sh
./scripts/setup-quality.sh  # один раз
./scripts/quality.sh        # также автоматически перед коммитом
```

По умолчанию выполняются быстрые локальные проверки: форматирование, линт, сложность Swift, границы модулей, EN/RU и поведение инструментов. Сборка приложения, загрузка движка и мутации не запускаются. Ошибки блокируют коммит. Hook сверяет staging с проверенными исходниками, включая изменения во время проверки.

По просьбе владельца 07.11.2026 GitHub Actions, обязательные PR и статусы удалены. Мейнтейнер может отправлять проверенные изменения прямо в main. Контрибьюторы могут использовать PR для ревью, но автоматических GitHub-запусков нет. Защита main от force-push и удаления сохранена.

## Полная проверка

При изменении архивных операций, core/UI и перед релизом запускаем локально:

```sh
./scripts/setup-quality.sh --full  # дополнительно устанавливает Muter
./scripts/quality.sh --full --base origin/main
```

Здесь добавляются сборка, XCTest/SwiftCheck, CLI/MCP, покрытие LLVM, CRAP(line), diff coverage и выбранные мутации. Это отдельный осознанный запуск, а не условие каждого коммита скрипта или документации. Проверяйте поведение, затронутое изменением, и фиксируйте команды/результаты.

## Правила и инструменты

| Проверка | Порог | Область/инструмент |
| --- | --- | --- |
| Форматирование и линт | Без диагностик и отличий | Swift-format из Xcode 16.4, SwiftLint 0.65.1; Sources, Tests, Package.swift |
| Размер | Файл ≤500, функция ≤80, тип ≤450 строк | SwiftLint; тело без пустых строк/комментариев |
| Сложность Swift | Цикломатическая ≤10, когнитивная ≤15 | swift-complexity 1.6.0 / SwiftSyntax; production Swift |
| Shell | Без диагностик и отличий | ShellCheck 0.11.0, shfmt 3.14.1; scripts/**/*.sh и Git hook |
| Python | Линт/формат; McCabe ≤10 | Ruff 0.14.4; все Python-инструменты/тесты |
| Модули и переводы | 0 циклов модулей; core независим от адаптеров; EN/RU совпадают | SwiftPM/компилятор, проверка каталогов |
| Полная: CRAP(line) | Среднее <5, максимум ≤30 | ArcboxCore; сложность + покрытие исполняемых строк LLVM |
| Полная: diff coverage | ≥80% изменённых исполняемых строк относительно base | ArcboxCore; LLVM → diff-cover 9.7.0 |
| Полная: поведение | Все примеры проходят | XCTest, SwiftCheck (100 примеров на свойство), CLI/MCP |
| Полная: мутации | Непустой запуск, все выбранные мутации обнаружены | Muter 16; ArchivePathPolicy/PartStream; сравнения/логические связки |

Нужны macOS и Xcode 16.4 / Swift 6.1.2. Python-зависимости закреплены с хешами в игнорируемом окружении. Версии и политика меняются согласованно. Не обходите hook и не скрывайте нарушения подавлениями.

CRAP(line) = `C² × (1 − coverage)³ + C`: здесь **покрытие строк**, не базисных путей. Функции SwiftSyntax сопоставляются с областями LLVM; несопоставленным назначается нулевое покрытие. Отчёты — `.build/quality/`. Без изменённых исполняемых core-строк знаменателя diff coverage нет. Численного порога покрытия UI/CLI нет; нужные UI-сценарии проверяются отдельно.

Мутации проверяют две критичные политики, не весь проект. Ошибки компиляции, тайм-ауты, выжившие мутации и пустые отчёты блокируют полную проверку. У Muter 16 есть проблема размещения мутаций после non-ASCII; выбранные файлы ASCII. Shell-линт не измеряет когнитивную сложность или покрытие.

## Проектирование и ревью

- **DRY:** поведение архиватора принадлежит ArcboxCore; адаптеры его вызывают. Объединяем доказанные правила, не внешнее сходство.
- **KISS:** прямые типы и нативные инструменты. Помощник называет реальную обязанность; функции не дробятся формально ради чисел.
- **YAGNI:** текущие требования «Открыть / Создать / Распаковать»; без гипотетических настроек и фреймворков.
- **SOLID / SRP:** оркестрация, процессы, метаданные, валидация и потоковая работа разделены. Для инструментов — тонкий shell-вход, именованные Python-этапы, отдельные Python-модули под Ruff.
- Проверяем сохранность оригиналов/атомарность, ошибки/отмену, значимые тесты, EN/RU, правдивую анимацию ожидания и Reduce Motion.

Инструменты помогают ревью, но не подтверждают принципы проектирования автоматически.
